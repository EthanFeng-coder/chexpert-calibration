# Training and Checkpoint Provenance

The calibration analyses in this repository are based on prediction probabilities generated by trained CheXpert models. The raw checkpoints are not redistributed in this public repository because they are large local artifacts and may encode assumptions tied to restricted medical-imaging data access.

## Included training script

The main training script used for the hierarchical CheXpert models is included as:

```text
scripts/train_libauc_hierarchical_ENSEMBLE.py
```

This script defines the hierarchical model, parent/child labels, augmentations, losses, checkpoint saving, thresholding, and evaluation logic used to train models whose checkpoints were later used to generate prediction files for calibration analysis.

## Minimal public analysis vs optional GPU training

The default environment files are for the public calibration/statistical-analysis scripts only:

```text
environment.yml
requirements.txt
```

GPU training/inference is optional and heavier. Its recorded environment is provided separately:

```text
environment-gpu.yml
requirements-gpu.txt
```

Recommended public analysis setup:

```bash
conda env create -f environment.yml
conda activate chexpert-calibration
```

Optional GPU/training setup:

```bash
conda env create -f environment-gpu.yml
conda activate chexpert-calibration-gpu
```

## Example training command pattern

The exact local data paths and checkpoints are intentionally not included. A reusable command pattern is:

```bash
CUDA_VISIBLE_DEVICES=1 python scripts/train_libauc_hierarchical_ENSEMBLE.py \
  --data_dir /path/to/chexpert_root \
  --train_csv train_hierarchical.csv \
  --val_csv valid_hierarchical.csv \
  --backbone maxvit_large_tf_512 \
  --batch_size 2 \
  --epochs 50 \
  --lr 3e-5 \
  --output_dir /path/to/output_dir \
  --gpu 0
```

## Calibration dependency

The public calibration scripts consume prediction arrays/CSVs derived from trained models, not raw checkpoints directly. To reproduce the exact manuscript analysis, a user needs:

1. Authorised access to the source datasets.
2. Trained checkpoints or equivalent model predictions.
3. The calibration/statistical analysis scripts in `scripts/`.
4. The restricted-data access and path layout documented by the user locally.
